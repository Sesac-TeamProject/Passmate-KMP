# 백엔드 전달사항 (KMP 학생 앱 → 백엔드)

**작성**: 2026-09-04 · **작성자**: 모바일(홍희표) · **받는 분**: 백엔드(전혜림)
**기준 서버**: 로컬 `local` 프로파일 · **단일 진실**: `http://localhost:8080/v3/api-docs`

이 문서의 모든 항목은 계약 문서가 아니라 **로컬 서버에 직접 찔러 본 결과**다. 재현 명령을 각 항목에
같이 적었다. 앱 쪽 대응은 이미 끝냈고, 여기 적은 것은 서버에서 정해 주셔야 하는 부분이다.

## 0. 먼저, 해결된 것

이전 전달 목록에 "미구현"으로 올렸던 결제 API 4종이 **모두 올라와 있다**. 앱이 부르는 경로
39개를 OpenAPI와 대조했고 **없는 경로는 0개**다.

| 경로 | 상태 |
|---|---|
| `POST /coins/charges` | 있음 |
| `POST /coins/charges/{chargeId}/confirm` | 있음 |
| `POST /rooms/{roomId}/entry-payments` | 있음 |
| `GET·PUT /users/me/payment-method` | 있음 |
| `POST /entry-payments/{paymentId}/cancel` | 있음 (앱은 아직 안 씀) |

확인 방법:

```bash
curl -s http://localhost:8080/v3/api-docs | python3 -c "import sys,json;[print(p) for p in sorted(json.load(sys.stdin)['paths'])]"
```

## 1. 시각에 오프셋이 없다 — 1순위

**무엇이 문제인가.** 응답 본문의 시각이 `LocalDateTime`이라 오프셋도 `Z`도 붙지 않는다.
받는 쪽은 이 값이 UTC인지 KST인지 문자열만 봐서는 알 수 없다.

**지금은 UTC다.** 같은 응답의 헤더와 본문을 비교했다.

```
Date 헤더         Fri, 04 Sep 2026 06:43:43 GMT
본문 lastLoginAt  2026-09-04T06:43:43.263979     ← 초까지 일치
```

세션 스냅샷도 같다. `GET /rooms/{roomId}/session`의 `currentQuestion.endsAt`이 UTC로 온다.

**왜 위험한가.** 앱은 스냅샷 본문에 "지금"이 없어서 `Date` 헤더를 서버 시각으로 쓴다.
표기가 다르니 둘을 같은 시계에 올려야 하는데, 그 판단이 **서버 배포 지역에 달려 있다.**
서버 JVM 시간대가 KST로 바뀌면 본문만 9시간 움직이고 헤더는 그대로라, 앱은 그 사실을
알 방법이 없다. 재접속했을 때 진행 중인 문항이 이미 끝난 것처럼 보이게 된다.

실제로 한 번 겪었다. 9월 3일 실측에서는 본문이 헤더보다 9시간 앞서 있어 앱이 보정을
넣었는데, 지금은 두 값이 같아져 그 보정이 오히려 타이머를 깨뜨리고 있었다. 오늘 걷어냈다.

**요청.** 응답 시각을 오프셋이 붙는 형식으로 주셨으면 한다.

- `LocalDateTime` → `OffsetDateTime`(또는 `Instant`)으로 바꾸고 `2026-09-04T06:43:43Z` 형태로 직렬화
- 어렵다면 최소한 **JVM 시간대를 UTC로 고정**하고 그 사실을 계약 문서에 명시

재현:

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/auth/dev-login \
  -H 'Content-Type: application/json' -d '{"key":"kmp-integration-check"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['accessToken'])")
curl -s -D - http://localhost:8080/users/me -H "Authorization: Bearer $TOKEN" | grep -iE "^date:|lastLoginAt"
```

## 2. `dev-login`은 로컬에만 두어 주세요 — 2순위

앱에 개발용 로그인 버튼이 있고, **붙어 있는 서버 주소가 사설 대역·루프백일 때만** 그려진다.
빌드 타입이 아니라 서버 주소로 가르는 구조라, 스테이징이 사설 IP를 쓰면서 `dev-login`을
켜 두면 그 버튼이 보이게 된다.

**요청.** `POST /auth/dev-login`을 **로컬 프로파일에만** 남겨 주세요. 스테이징에도 켜야 할
사정이 생기면 미리 알려 주시면 앱에 빌드 타입 검사를 함께 얹겠다.

`/auth/dev-login`은 계약 문서(`contracts/rest-api.md`)에 없다. 개발 전용이라 넣지 않았는데,
계약에 없는 API를 앱이 부르는 셈이라 팀에서 한 번 정리하면 좋겠다.

## 3. Google 로그인 — 웹 클라이언트 ID가 필요하다 — 3순위

앱이 여는 `GET /auth/oauth/google?client=mobile`은 **서버에 없다**(404). 서버 auth 경로는
`/auth/login/{provider}` · `/auth/refresh` · `/auth/logout` · `/auth/dev-login` 넷뿐이다.

서버·계약은 `POST /auth/login/{provider}`에 Google **ID 토큰**을 넘기는 방식이다. 앱이 그 토큰을
받으려면 SDK에 `serverClientId`로 **웹 클라이언트 ID**를 지정해야 서버의 `aud` 검증을 통과한다.

**요청.** 웹 클라이언트 ID를 알려 주세요. 그게 있어야 앱 SDK 연동을 시작할 수 있다.
지금 앱에서 회원 기능(마이페이지·코인·정산)은 개발용 로그인으로만 들어갈 수 있다.

## 4. OX 문항에 `choices`가 없다

`QuestionStartedPayload.choices`가 nullable이고, 실측에서 OX 문항은 `choices: null`로 온다
(`type=OX, answer="O"`).

앱은 OX일 때 보기 목록을 `O`/`X`로 채워 넣도록 고쳤다. 다만 **보기 라벨을 누가 정하는지**가
정해져 있지 않다. 서버가 정하는 게 맞다면 `choices: ["O","X"]`로 실어 주시고, 앱이 정하는 게
맞다면 계약 문서에 그렇게 적어 두면 좋겠다.

---

## 5. `PARTICIPANT_JOINED` · `PARTICIPANT_LEFT`가 발행되지 않는다

이전 세션 기록이다. 이벤트 enum에는 있는데 실제로 발행되지 않아 **대기실 참가자 목록이
실시간으로 늘지 않는다**. STOMP는 OpenAPI에 없어 이번에는 재확인하지 못했으니, 이미 고쳐졌다면
알려 주세요.

## 6. 방 목록에 빠진 필드

앱 DTO는 이미 서버 응답에 맞춰 두어서 **깨지지는 않는다.** 다만 시안이 요구하는 정보가 없어
화면에서 비워 두거나 따로 조회하고 있다.

| 응답 | 없는 필드 | 앱에서 생기는 일 |
|---|---|---|
| `PublicRoomResponse` | `pin` | 목록에서 바로 입장하지 못하고 방 상세를 한 번 더 부른다 |
| `PublicRoomResponse.host` | 등급·평균 별점 | `userId`·`nickname`만 있어 시안의 선생님 뱃지를 못 그린다 |
| `RoomSummaryResponse` | `questionCount`, `host` | 참여한 방 목록에 문항 수·선생님을 못 보여 준다 |

우선순위는 낮다. 다만 `PublicRoomResponse.pin`은 목록에서 입장까지 왕복이 한 번 줄어서
체감 차이가 있다.

## 7. 방 리포트 응답이 계약과 다르고 `pin`이 없다 — 2순위

`GET /rooms/{roomId}/results`(M-14 방 리포트)는 계약 문서와 **필드 이름이 다르다.**
앱 DTO를 계약대로 두었더니 제목이 빈칸으로 그려졌다. 실측에 맞춰 앱을 고쳤으니
**계약 문서(`contracts/rest-api.md`)를 서버 실측에 맞춰 갱신해 주세요.**

| 계약 문서 | 실제 서버 | 값 |
|---|---|---|
| `roomTitle` | `title` | |
| `dateLabel` | `startedAt` | ISO 날짜시각 |
| `students[]` | `participants[]` | |
| `summary.studentCount` | `summary.participantCount` | |
| `summary.avgAccuracyPercent` | `summary.avgCorrectRate` | **0.0~1.0 비율** (퍼센트 아님) |
| `questions[].questionNo` | `questions[].orderNo` | |
| `questions[].title` | `questions[].content` | |
| `questions[].accuracyPercent` | `questions[].correctRate` | **0.0~1.0 비율** |
| `questions[].aiFeedbackCount` | `questions[].aiAnalysisCount` | |

**요청 1.** 응답에 **`pin`을 넣어 주세요.** 시안 M-14의 부제가
"8/22(금) 진행 · 종료된 방 · **PIN 482 913**"인데 지금은 PIN을 낼 방법이 없다.
앱은 `roomId`만 들고 이 화면에 들어오고, 리포트 응답에도 목록 응답에도 pin이 없다.
지금은 pin 조각을 통째로 생략해 두었다.

**요청 2.** `summary.topScore`와 `participants[].isGuest`도 없다. 시안에 최고점과
게스트 구분이 있어서 지금은 비워 둔다. 우선순위는 pin보다 낮다.

**재현.**

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/auth/dev-login \
  -H 'Content-Type: application/json' -d '{"key":"kmp-integration-check"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['accessToken'])")
curl -s http://localhost:8080/rooms/22/results -H "Authorization: Bearer $TOKEN" | python3 -m json.tool
# title·startedAt·participants는 있고 pin은 없다
```

## 8. `QUESTION_ENDED`에 보기별 응답 분포가 없다 — 3순위

시안 M-04(문항 결과)의 절반이 **"응답 분포"** 영역이다. 보기마다
`① REQUIRED  4명` 처럼 인원과 막대를 그린다. 그런데 이벤트에는 총
정답자 수만 있다.

```
QUESTION_ENDED  { orderNo, answer, explanation, correctCount }
```

**요청.** 보기별 제출 수를 넣어 주세요. 예:

```json
"choiceCounts": [4, 1, 1, 0]
```

없으면 이 영역을 그릴 수 없어 화면이 시안과 다르게 남는다.
`M-T2` 진행 리모컨은 같은 정보를 이미 보여 주고 있으니(A/B/C/D 인원 막대)
서버 안에는 있는 값으로 보인다.
